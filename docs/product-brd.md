# 国际化 Leads 搜寻产品 BRD

## 1. 文档信息

- 产品名称：International Leads Finder
- 文档类型：BRD
- 当前版本：v1.0
- 文档日期：2026-05-14
- 适用阶段：MVP 到 V1

## 2. 背景与目标

### 2.1 背景

当前国际业务获客中，公开社媒线索的搜集方式仍较为分散，常见问题包括：

- 搜索依赖人工，搜词策略不稳定
- 公开结果中的手机号、页面链接、摘要信息分散在不同位置
- 缺少统一的结构化输出格式，后续人工筛选成本高
- 搜索过程不可追踪，难以复盘哪些 query 有效
- 结果不能稳定沉淀到数据库，难以做重复利用和团队协同

### 2.2 产品目标

本产品目标是构建一个面向国际公开线索搜索的工作台，帮助业务人员通过“搜索词 + 平台 + 区号”的方式，批量发现 Facebook / Instagram 的公开 leads，并完成：

- 自动生成搜索 query
- 调用 Brave Search 获取公开结果
- 结构化抽取手机号、标题、摘要、链接等信息
- 对结果做基础清洗、去重和质量分层
- 以标准结构保存到 Supabase
- 在前端展示任务进度、任务历史和结构化线索结果

### 2.3 成功定义

产品成功的最低标准包括：

- 用户可以在一个页面中发起搜索任务
- 系统能实时展示任务进度和查询状态
- 结果能沉淀为结构化 leads 数据
- 结果导出格式与“巴西汽车汽配 Facebook 线索表”对齐
- 数据可以长期保存并支持后续筛选与复查

## 3. 目标用户

### 3.1 核心用户

- 外贸业务员
- 国际市场开发人员
- Leads 搜索执行人员
- 社媒公开数据研究人员

### 3.2 用户特征

- 熟悉国家、行业和平台维度的搜索需求
- 更关心“是否能快速找到可联系对象”
- 需要可复制、可导出、可复查的结构化结果

## 4. 用户问题

用户当前的核心问题包括：

- 不知道哪些搜索组合最有效
- 手工复制号码和页面信息效率低
- 同一条线索容易重复出现
- 缺少统一质量标准，筛选工作耗时
- 导出结果格式不统一，无法直接进入 CRM 或后续跟进流程

## 5. 产品范围

### 5.1 MVP 范围

MVP 包含以下能力：

- 基于输入条件生成搜索任务
- 支持 Facebook 与 Instagram 两个平台
- 支持 Brave Search API 搜索公开网页结果
- 自动提取手机号、标题、摘要、平台、来源链接
- 进行基础去重与质量分层
- 将任务、事件、线索写入 Supabase
- 前端展示任务状态、任务历史、线索结果
- 支持导出全量 CSV 和 refined CSV

### 5.2 非目标

当前版本不包含以下能力：

- 登录 Facebook / Instagram 后的深度抓取
- 私有数据抓取
- 自动发信、自动私信、自动 CRM 跟进
- 复杂权限体系
- 多用户组织管理
- AI 语义打分和自动翻译增强

## 6. 产品方案概述

### 6.1 核心流程

1. 用户输入搜索词、国家/城市、区号、行业组、线索池类型、平台等参数
2. 系统根据参数生成多条 query plan
3. 后端调用 Brave Search API 获取公开结果
4. 系统从标题、摘要、URL 等字段中抽取结构化线索
5. 系统完成去重、质量分层和标准化格式转换
6. 任务过程通过事件流实时返回前端
7. 任务、事件、线索数据写入 Supabase
8. 用户在前端查看结果、筛选、导出和复制

### 6.2 搜索模式

当前产品采用公开搜索驱动模式，典型 query 结构为：

`搜索词 + site:facebook.com / site:instagram.com + 区号 + 地域词 + 修饰词`

示例：

- `site:facebook.com autoparts importer "Brazil" "+55"`
- `site:instagram.com electronics wholesale "Mexico" "+52"`

## 7. 功能需求

### 7.1 搜索任务创建

用户可配置以下字段：

- 搜索词
- 区号
- 国家
- 城市
- 行业组
- 线索池类型
- 搜索语言
- Brave 国家参数
- 最大查询数
- 平台选择

功能要求：

- 搜索词和区号为必填
- 平台至少选择一个
- 最大查询数支持限制范围
- 国家可联动默认区号和搜索语言

### 7.2 Query Plan 生成

系统根据用户输入自动生成 query plan。

生成逻辑要求：

- 平台维度可组合
- 国家、城市、行业关键词参与组合
- 支持按 pool type 注入不同修饰词
- 控制最大 query 数，避免请求失控
- 前端可预览 query plan

### 7.3 公开结果搜索

后端通过 Brave Search API 发起请求。

功能要求：

- 支持按 query 顺序执行
- 支持基础失败重试或错误记录
- 支持任务取消
- 支持任务实时进度更新

### 7.4 结构化抽取

对 Brave 返回结果进行结构化清洗，核心字段包括：

- 标题
- 摘要
- 平台
- 来源链接
- 规范链接
- 手机号
- 命中 query
- 国家
- 城市
- 行业组

功能要求：

- 从标题、摘要、URL 中提取号码
- 同一线索保留命中的多个 query
- 生成统一 dedupe key

### 7.5 去重与质量分层

系统对结果进行基础质量分层：

- `refined`：较高可用性线索
- `broad`：宽口径候选线索

功能要求：

- 去重逻辑基于 dedupe key
- 同线索重复命中时合并 query 信息
- 允许线索从 broad 升级为 refined

### 7.6 任务进度展示

前端需展示：

- 当前任务状态
- 已完成 query 数 / 总 query 数
- 总 leads 数
- refined leads 数
- 当前 query
- 任务事件日志

功能要求：

- 使用实时事件流展示
- 任务完成后仍可回看历史结果

### 7.7 任务历史

前端需支持最近任务列表。

功能要求：

- 展示最近任务基本信息
- 支持点击重新查看任务详情
- 展示任务创建时间、线索数、进度和状态

### 7.8 Leads 结果表

前端需以结构化表格展示结果。

展示字段包括：

- 国家
- 行业组
- 公司/页面
- 手机
- Facebook 链接
- 类目英文
- 类目本地语言
- 命中关键词
- 摘要

辅助能力包括：

- 按质量层级筛选
- 按平台筛选
- 关键词检索
- 复制手机号
- 查看摘要详情
- 打开原链接

### 7.9 导出

导出结构参考“巴西汽车汽配 Facebook 线索表”。

当前导出能力包括：

- 全量结构化 CSV
- refined CSV

导出列固定为：

- 国家
- 行业组
- 公司/页面
- 手机
- Facebook链接
- 类目英文
- 类目本地语言
- 命中关键词
- 摘要

### 9.1 核心接口

当前建议接口包括：

- `GET /api/health`
- `GET /api/options`
- `GET /api/jobs`
- `POST /api/jobs`
- `GET /api/jobs/:id`
- `GET /api/jobs/:id/events`
- `GET /api/jobs/:id/leads`
- `GET /api/jobs/:id/stream`

### 9.2 接口目标

- 健康检查
- 配置下发

- 任务回看

- 结果导出

## 10. 前端需求

### 10.1 页面结构

建议采用单页工作台布局：

- 左侧：搜索配置、最近任务、导出标准说明
- 右侧：当前任务概览、任务日志、结构化 leads 表

### 10.2 关键交互

- 提交搜索后进入任务执行态
- 实时更新任务进度
- 点击历史任务恢复上下文
- 在表格中快速筛选和查看细节
- 支持复制号码和打开原页面

### 10.3 可用性要求

- 页面需适配桌面和移动端基础浏览
- 表格区域支持横向滚动
- 任务完成后状态清晰可辨
- 导出按钮在无任务时禁用

## 11. 非功能需求

### 11.1 性能

- 单次任务应在合理时间内完成
- 前端需在任务进行中保持可响应
- 最近任务和单任务结果回看应快速返回

### 11.2 稳定性

- Brave API 失败时记录错误并反馈状态
- Supabase 不可用时需保留可诊断信息
- 任务取消后不再继续执行后续 query

### 11.3 安全

- API key 仅保存在服务端环境变量
- `.env` 不进入 git 仓库
- 服务端 key 后续需支持轮换

### 11.4 可维护性

- 搜索、清洗、存储、前端展示模块解耦
- Query 生成逻辑可持续扩展到更多国家和行业

## 12. 关键指标

建议跟踪以下指标：

- 单任务平均 leads 数
- refined 占比
- 查询成功率
- 每个 query 的命中率
- 任务完成率
- 导出使用率
- 重复线索占比

## 13. 风险与约束

### 13.1 外部依赖风险

- Brave API 配额和稳定性
- 社媒公开页面摘要质量不稳定
- 搜索结果对地区、语言和时间敏感

### 13.2 数据质量风险

- 公开摘要中的号码可能不完整
- 同一页面可能存在多个号码或无效号码
- 结果可能包含非目标客户

### 13.3 技术约束

- 当前基于公开搜索，不等同于平台内深爬
- 任务质量高度依赖搜索词策略
- 前端在 `file://` 预览模式下无法直接调用后端接口

## 14. 里程碑建议

### Phase 1：MVP

- Brave 搜索接入
- Query 生成
- 结构化抽取
- Supabase 入库
- 单页任务工作台
- CSV 导出

### Phase 2：V1

- 更多国家和行业模板
- 结果标签增强
- 更细的质量评分
- 更强的筛选和批量操作
- Excel 导出

### Phase 3：增强版

- AI 摘要标准化
- 多用户协作
- CRM 对接
- 自动化监控和定时任务

## 15. 验收标准

产品上线前至少满足以下验收项：

- 可成功创建搜索任务
- 可显示结构化任务进度
- 可在任务完成后查看 leads
- 可写入 Supabase 三张核心表
- 可导出符合参考结构的 CSV
- 可查看最近任务并重新载入详情
- 可对结果执行基础筛选和复制操作

## 16. 当前版本结论

本产品适合作为国际市场公开 leads 搜索的轻量工作台，先解决“搜到、清洗、沉淀、复查、导出”五个核心问题。MVP 的重点不是替代所有爬虫或销售系统，而是把公开搜索这条链路做成稳定、标准、可复用的产品能力。
